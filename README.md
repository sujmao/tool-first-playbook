# 工具優先：充分利用現有工具的優勢，不重複造輪子

> 一份「經驗總結遷移」repo —— 把一次真實的批量自動化任務中「用對工具、少走彎路」的
> 方法論與踩坑記錄沉澱下來，供其他人複用。

## 一句話主旨

**先盤點現有工具的能力，讓成熟的工具做它最擅長的事（鑑權、反爬、下載、合併），
自己只寫一層薄薄的膠水，而不是重新造輪子。**

## 這個 repo 是甚麼

- **一次案例**：驅動 [Bili23-Downloader](https://github.com/ScottSloan/Bili23-Downloader)
  自帶的 MCP 介面，批量下載某個 B 站空間的全部投稿，並在事前估算總大小、事後統一重命名。
- **一套方法論**：甚麼時候該「用現成工具」、甚麼時候才「自己動手」，以及中間的判斷信號。
- **一份踩坑清單**：把實際撞過的坑逐條記錄，附「原因 + 避開方式」，讓下一個人不用再踩。

## 適用讀者

- 想做「自動化下載 / 批量處理」，但不想從零逆向目標平台的人。
- 面對一個「已有桌面應用 / 已有 CLI / 已有 MCP」的任務，猶豫該不該自研的人。
- 想把手上的排程任務從「人肉點擊」變成「腳本編排」的人。
